# CYBER RUN｜無限ラン V0.9 開発・検証報告（2026-10-24）

## 最新のユーザー方針

- **試遊は GitHub Pages。友達との公開が Google Sites（直接HTML埋め込み）。** この2つを混同しない。
- ユーザーは V2.3.1 の手作りコースを「いい感じ」、単調さは大きく改善と評価。コイン密度84px・穴に触れただけでダメージにならない仕様は維持。
- **現行の難易度はあくまで「序盤として許容」**。無限ランでは奥まで進むほど高難度にしなければならない。
- 初見殺しは許容するが、物理的に避けられない組み合わせ・誤判定・穴の縁での即時ダメージは拒否。
- 距離のみをスコアとし、道標コインは得点0。HP3、2段ジャンプ、長押ししゃがみ。

## 今回の実装

- `infinite-level-v1.js` — V2.3.1で実機好評だった手作り16区間のうち、冒頭3つを毎回同じ短い準備運動とし、その後は乱数シードで分岐。最後までGOALを置かず無限生成する。
- `game-infinite-v1.js` — 有限コースのゲーム/エフェクト/HP/距離スコア/コイン/穴の遅延ダメージ処理を継承し、終了条件をゲームオーバーのみに変更。無限の難度帯・連続区間番号をHUDに表示する。BESTは別のlocalStorageキーで保存（旧記録の上書きなし）。開発用テストシードのオプトインあり。
- `infinite-playtest-v1.html` — 開発ブランチの5つのJavaScriptを読み込むQA用HTML。
- `tests/infinite-v1.test.js` — seed再現性、他seedとの差異、各速度帯での通過、±60ms入力ズレ、遠方までの難度上昇、ベスト記録独立の基本設計条件を検証。
- `tools/browser-infinite-v1.cjs` — キーボードイベントを本物のChromiumのゲームに入力し、120Hz物理と画面描画が動く状態で **220秒の通し走行**を確認。
- `playtest-v24/index.html` — `main` 内の新規・独立の1ファイル式試遊候補。ゲーム・CSS・生成器をHTML内に完全同梱、noindex。
- `tools/browser-pages-v24.cjs` — mainからcheckoutした1ファイルを直接Chromiumで通し検証する、より強い検証。GitHub Pagesの実際のHTTPS応答そのものを検証するものではない。

## 難易度曲線（暫定値。人間の試遊で再調整）

| 経過時間 | HUD表示 | 内容 |
|---|---|---|
| 0〜約10秒 | WARMUP | 毎回同じ3区間の指ならし、既存の完成度を維持 |
| 約10〜30秒 | BUILD | 初期の手作り地形から抽選。操作を覚えながらリズムを作る |
| 30〜60秒 | COMBO | 高低差、リング、しゃがみの組合せ候補を増やす |
| 60〜100秒 | PRESSURE | 難度の高い地形を定期的に選び、緩急も残す |
| 100〜160秒 | EXPERT | 高難度モチーフの連続2区間が増える |
| 160秒〜 | ENDURANCE | 3区間以上の高難度連続チェーン。経過時間100秒ごとに長さを追加（安全上限12）、時々短い変化で息継ぎ |

**難しさの設計は障害物数を機械的に増やすことではない。** 速度が上限の1150px/sに達してからも、失敗なく実行し続けるアクションの長さ・密度によって習熟度が記録へ反映される。

## 制約と品質ゲート

1. すべての区間は `handcrafted-level-v2.js` が物理リプレイによって通過証明済みのパターンのみを使用する。生成器も連携順を制約する（隣接同一区間を避け、経験帯に合わないパターンを除外）。
2. すべてのパターンが出入口で地上・ジャンプ回復状態になっていることを各パーツのリプレイテストで検証済み。危険なパーツ境界がないかは無限連続実ブラウザテストでも確認する。
3. 生成されたルートは一つのseedで再現可能。HPによる回復抽選は地形選定とは別の乱数を使用する。
4. HPが足りない時の回復はレア発生のみ、既存道標コインのうち安全な地上箇所へ置換して提供する。道標の得点0の原則は維持する。
5. 無限生成の公開版・ランキングにはまだ移行しない。身内のGoogle Sites版を改変しない。
6. 以前の55秒固定チャレンジ `/playtest-v23/` は別途残し、本人が比較試遊できるようにする。
