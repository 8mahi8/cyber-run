## 次のチャットで優先して話し合う設計議題

### 1. コインによる誘導は何を教えるか

- ジャンプ開始の位置、2段ジャンプする場所、着地点、しゃがみ通路の低い軌道、反発リングに入る角度などを「連続した点の列」で直感的に示せるか。
- 空中リングや崩れる足場など、**初めて登場するギミック**は、いきなり複合コースで使うのではなく、短い安全な単独場面で性質を伝えてから難しくするべきか。
- コインを全て拾わないと失敗する「強制正解ルート」にはしない方がよいか。別解や上級者のショートカットを残すか。
- コインの色/輪郭/動線と、実際の障害物・地形・ジャンプ高さとの視覚的な混同を防ぐ。高速走行でも先読みできるかを評価する。

### 2. 収集・報酬の有無（未決定）

- **推奨する初期案**: コインはまず「道標」であり、収集しても距離スコアやFirebaseランキング順位には影響させない。装飾として見えるだけにするか、接触で消える演出を付けるかは相談する。
- 以前は「コイン廃止、距離だけ」が正式な方針だった。今回の発言は**誘導としてのコインを復活させたい可能性**を示すが、数・スコア・ミッション・取得判定まで決まったわけではない。
- コインがゲーム内通貨になる、ショップを作る、週間ランキングを足すなどの機能拡張は提案しない。

### 3. 難易度の作り方

- 人間が操作する際に難しい＝見えなくて反応できない、ではない。**やるべき操作が分かったうえで、正確に実行する難しさ**を目指す。
- コイン等の道標を用いてルートの理解を補助し、**操作の切替・ギミックの連鎖・高低差・タイミングの要求**で難易度を上げる。
- 既存の「ジャンプ、2段ジャンプ、長押ししゃがみ、崩れる床、空中リング、ジャンプ台、しゃがみ必須ゲート」について、初見にわかるか、慣れた後も面白いかを人が確認する。
- **しゃがみ必須の地形**と、ジャンプでも回避可能な自由攻略ルートの両方を意図的に残す。

### 4. 手作りマップの「章」と教え方

提案のみ（未確定）:
1. 最初は操作そのものとコイン誘導の意味を数秒で理解する。
2. 新ギミックを**一つずつ安全に体験**し、見た目と作用を学ぶ。
3. ギミックの組合せ・操作切替を増やして難しくする。
4. 最後に学んだ要素を複合した高密度チャレンジを置く。

完成ルートの基準を決めてから、既存の全20区間を並べ直すか、長さを見直すか、全く新しい区間を手作りするか決める。**20区間・65秒は現行試作の事実であり、最終仕様として固定されたものではない。**

### 5. 視認性・速度との両立

- 最高速度1150 px/sで先が見えなくなる問題を考慮し、手作り配置で予告距離・視線誘導を作る。
- スピード感はユーザーが肯定的に評価した要素なので、**簡単にするための一律減速**は前提にしない。
- 実画面上で道標がルートを示すか、障害物と混同しないか、押すタイミングの誤誘導を起こさないかを評価する。

## 話し合いの進め方（次回AIへの指示）

1. **まずユーザーへ設計を提案・比較する。コード実装はしない。** 新たな問いを大量に連続で投げない。最初は「コインを道標に使う場合、スコアなし誘導専用を基本案にする」という整理を示して、ユーザーの評価を聞く。
2. 地形の具体例（例: 円弧を描くコイン列でジャンプ、着地点へ水平につなぐ列、しゃがみ通路に沿った低い列、空中リングへ向かう列）を**設計例として**議論する。見た目を画像として生成するのは本人が画像を依頼した場合だけ。
3. 難易度・ギミック密度・コイン誘導・章構成を合意したら、この資料に**決定済み/未決**を分けて更新する。
4. **設計が固まった後のみ**、別の開発コミットでマップを実装し、物理リプレイ・独立入力ジッター・実ブラウザ画面・ユーザーの試遊を検証する。
