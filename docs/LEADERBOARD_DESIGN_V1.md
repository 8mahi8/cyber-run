# CYBER RUN｜オンラインランキング仕様 V1（設計確定）

決定日: 2026-10-23
状態: **仕様確定・未実装**。ユーザー確認済み。Firebaseの接続、ルール変更、本番Google Sites更新は行っていない。
開発: `dev/trajectory-first-v07`。V0.5本番、V0.6/V0.7試遊ページの既存挙動は変更しない。

## 1. 何を競うか

- **全期間ランキング（ALL-TIME）のみ**。週間・日間リセット、シーズン、報酬、対戦ログ、リプレイ機能なし。
- 基準は**1プレイの最高走行距離（m）**。累計距離ではない。
- **1人1枠を目標**に、同一認証UIDについて最高記録1件を表示。スコアが上がった場合だけ更新し、低い記録は上書きしない。
- 表示は上位20人＋自分の最高記録と現在順位。順位は同点なら同順位として表示し、並びは安定化のためUIDの順で固定してよい。無理な全件取得は避ける。
- 友達同士の小規模利用。スコアを競うことが目的で、複雑な機能は追加しない。

## 2. 学校・開発・試遊の環境（絶対に混同しない）

| 役割 | 実体 |
|---|---|
| 開発・履歴・テスト | GitHubの開発ブランチ・Draft PR |
| ユーザー本人の試遊 | **GitHub Pages**上の独立した試遊URL |
| 学校で友達と遊ぶ | **Google Sites**の「埋め込む → 埋め込みコード」に**単一のHTML/CSS/JSコードを直接貼り付ける** |
| スコア共有 | **Firebase Realtime Database** |
| 認証 | Firebase Authenticationの**匿名サインイン**。ログイン画面は不要 |
| 費用 | **Sparkの無料枠内のみ**。有料プランや課金を前提にしない |

学校版はGitHub PagesのURLやiframeを埋め込んで表示する方式**ではない**。Google Sitesのコード埋め込み方式を優先し、iPad Safariの埋め込み内で実際にFirebaseの匿名認証・保存・読出しが通るかテストする。

Firebase Web SDKを必要とする場合は、配布コードを単一HTMLにまとめつつ、公式SDKの読込み先だけを外部に持つ設計は許容候補。ただし、学校ネットワーク・Google Sites iframe・Safariの追跡防止によりSDK/Authが失敗する可能性がある。**接続に失敗してもゲームの開始・走行はできる**ようにする。

## 3. UI・使い方

1. 初回ランキング登録時に任意の**ニックネーム（2〜16文字）**を入力。実名・メールアドレス不要。適切な表示文字への制限と画面への安全なテキスト表示を行う。
2. ホーム/ゲームオーバーから「RANKING」を開ける。プレイ画面の視認性を妨げる常時表示はしない。
3. ランキングでは順位・名前・最高mを表示。自分の行は目立たせる。「YOUR BEST / あなたの順位」は上位20人未満でも別欄に表示。
4. **ゲームオーバー時**に、それまでの自己ベストを上回る走行距離なら送信する。同じ値・低い値では送信しない。途中離脱・一時停止では送信しない。
5. オンラインが使えない場合、「ランキングを読み込めません」と表示し、プレイと端末内ベスト記録は維持する。データベース未構成ならランキングだけ無効化し、ゲームが壊れないようにする。
6. 表示名は後から変更可能。ただし不適切な名前の対策やブロック手段は最小限用意する。名前重複はありうる。

## 4. Firebaseデータ設計（予定）

```json
{
  "cyberRun": {
    "leaderboards": {
      "v1": {
        "scores": {
          "<anonymous-uid>": {
            "name": "PLAYER",
            "bestMeters": 1234,
            "updatedAt": 1792700000000
          }
        }
      }
    }
  }
}
```

- `<anonymous-uid>` は実際のUIDに置き換える。名前そのものをキーにしない。
- 表示上の上位20件: `orderByChild('bestMeters')` と `limitToLast(20)` で取得し、画面上では降順に並べる。`.indexOn:['bestMeters']` をルールに追加する。
- 自分の行は `scores/{auth.uid}` を読む。自分の順位を正確に表示する際は、件数・料金・読込みを考慮したクエリで高得点者の数を算定する（小規模利用前提で実装後に計測）。
- 自己ベスト更新は原子的なトランザクション（`runTransaction`）を使用し、同時更新で低い値が勝たないようにする。
- 書込み内容は名前・スコア・更新日時程度に限定。メールアドレス、実名、対戦ログ、端末情報などは収集しない。
- テストデータは本番とは**別のパス**または**別のテストプロジェクト**に置き、プレイテスト記録を公式ランキングへ混ぜない（接続前に明示）。

## 5. 必要最低限のルール・不正対策

- 誰でも無制限に書き込めるルールは禁止。**認証UID自身の行だけ書込み可能**にする。
- `bestMeters` は非負整数、範囲上限あり、既存の自己ベストから**減少不可**。フィールドの型・名前の文字数・余分なフィールドなし・削除不可をSecurity Rulesで検証。
- 可能ならスコア更新時のレート制限・異常な距離・名前の不正文字を検証し、不正が起きた場合にレコードを無効化できる運用を準備。
- **重要な限界**: ブラウザ側の値を改変して偽の走行距離を送信することを、無料の匿名クライアント構成だけで完全に防ぐことはできない。「認証UIDごとに1枠」は厳密に「人間1人につき1枠」を意味しない。匿名アカウントを新規作成した場合、別端末・別ブラウザ・プライベートモード・ブラウザデータ消去・Google Sites iframeの保存制限などでも別IDになりうる。
- これらの限界は、友達同士で遊ぶという目的に応じて受容。サーバーで全プレイを再実行するような高コストな仕組みはV1では採用しない。

## 6. Firebase無料枠と運用上の制約

- Firebase公式資料ではRealtime DatabaseのSparkプランの同時接続は**最大100**。少人数の身内用なら想定上の余裕はあるが、通信量や保存量の他の無料枠も定期確認する。
- Sparkでは上限に達すると追加課金ではなくサービスが利用できなくなる場合がある。**課金プランへ自動移行しない**。
- DB接続失敗時や学校のネットワークで匿名Authが使えない場合は、ゲーム本体を止めずランキングのみ利用不可とする。
- Firebase Web SDKのオフライン書込みは、Webではタブを閉じる前のサーバー同期を保証しない。成功表示は**サーバーからの確定応答後だけ**にする。

## 7. 実装前の最終確認ポイント

- Firebaseプロジェクトの `databaseURL`、Web設定（公開してよい構成キー）、**匿名認証の有効化**を接続時に確認する。未知のFirebaseプロジェクトや他ゲームの本番DBを勝手に使わない。
- データベースSecurity Rulesをエミュレーター/テスト環境で検証し、**他人の行の改変・スコア減少・スコア型不正・削除**を拒否する。
- Google Sites直接埋め込み、iPad Safariで匿名UID永続化・スコア保存・表示・通信途絶時の振る舞いを試験する。
- 既存のV0.5・V0.6・V0.7試遊ページ、Google Sites本番HTMLは、本人が明示的に切替承認するまで変更しない。
