# CYBER RUN V0.7｜「情報密度」外部調査と設計ルール

調査日: 2026-10-23
対象: V0.6試遊後の「単調・簡単・情報密度が低い」というプレイヤー評価
状態: **設計調査。実装・数値目標の達成は未確認。**
開発ブランチ: `dev/trajectory-first-v07`（V0.6 GitHub Pages試遊ページ・公開版には影響させない）

## 結論

「情報密度」を単一の障害物個数や画面の派手さと見なさない。CYBER RUNでは4種類に分離する。

1. **操作密度** — 10秒に何回、意味のある入力を要求するか（ジャンプ、追加ジャンプ、しゃがみ開始・解除等）。単純な入力連打だけでは不十分。
2. **状況変化密度** — 足場・高度・地上/空中・障害物の性質・操作順序がどれだけ変わるか。同じ地上障害物の色や順番を変えただけではカウントしない。
3. **画面/演出密度** — 背景の動き、環境的な因果（障害物に付随する機械・ゲート）、音を使わないでも読める速度/成功のフィードバック。情報ではなく単なる装飾なら危険物の視認性を下げないこと。
4. **予測可能性と読みやすさ** — 画面内に次の行動を先読みできるだけの危険物・着地点があり、必要な視覚情報が装飾に埋もれないこと。密度と両立すべき安全制約。

## 外部資料の要点（出典と事実を区別）

### A. BIT.TRIP RERUNNER 公式 RUNNER MAKER マニュアル
https://www.rerunner.game/tutorial

- 公式ツールには LOW/MEDIUM/HIGH の *obstacle density layer* がある。HIGHはMEDIUMに障害物を追加、LOWは削除するモデル。
- 「Path Objects」と「Cosmetic Objects」を明示的に分ける。装飾物は行動のヒントも担当する。
- 音楽のフレーズのようにパターンを反復すると流れを理解しやすいこと、難易度上昇よりも flow を重視すること、難易度ごとの異なるプレイ内容を用意することが解説されている。
- **CYBER RUNへの翻訳（提案）**: 同じ操作フレーズから密度違いのコースを派生させるが、密度を増す際はジャンプの余裕を失わせるのではなく「次の操作への連携」を追加。背景レイヤーは当たり判定・コースレイヤーと分離する。

### B. Sonic Team ディレクターインタビュー（GAME Watch）
https://game.watch.impress.co.jp/docs/interview/1440960.html

- 飯塚氏は「速度のパラメータを上げるだけでは速さを面白さにできない。コース設計が重要」という趣旨を述べている。
- SEGA公式プランナーの採用インタビューでも、スピードの核を壊さず、単発ではなく複合的な遊びを作る旨の説明がある。
- https://www.sega.co.jp/recruit/interview/planner04/
- **翻訳**: V0.6で好評の最高速・加速を維持して「速度だけで気持ちよさを作る」方向から「疾走中の状況変化によって速度が生きる」方向へ。

### C. Celeste 制作者インタビュー（Nintendo）
https://www.nintendo.com/jp/topics/article/19b31c18-6544-11e8-b9c0-063b7ac45a6d

- 難しい箇所は何をすればよいか理解しやすくし、すぐに再挑戦できるよう調整。テストで配置を何度も直す。
- 別記事では難度が高い場面は背景を簡素にする意図を説明。
- https://automaton-media.com/articles/newsjp/20180131-62024/
- **翻訳**: 「難しい操作」と「何をするか分からない」は分ける。危険物の形・色・予告・床の位置は装飾より高い視覚優先度で描く。

### D. Super Mario 3D Land/World 4段階構成
https://www.gamedeveloper.com/design/the-secret-to-i-mario-i-level-design
- 林田宏一氏の紹介する導入→発展→転調→締めの流れ。一つの仕掛けを理解させ、組み合わせ、予想外に使わせる。
- **翻訳**: 延々と独立した障害物を出すのではなく、4〜8秒単位の短い「行動フレーズ」にテーマと展開を持たせる。例えば「低い足場へ着地→天井をしゃがんで抜ける→着地前に再跳躍→次の段へ」。

### E. Canabalt 作者インタビュー（Game Developer）
https://www.gamedeveloper.com/design/the-tip-of-the-iceberg-storytelling-and-reactive-design-in-i-canabalt-i-and-i-capsule-i-
- 作者Adam Saltsman氏によると、建物は走行速度を考慮して逐次生成され、ジャンプが到達可能な中で面白い難しさを作る。
- **翻訳**: V0.7の軌道先行生成器の発想は妥当。ただし「到達可能性」は面白さの下限条件であり、連続状況変化・入力猶予・画面密度は別途設計する必要がある。

### F. Level Design の視覚ノイズと認知（Game Developer）
https://www.gamedeveloper.com/design/the-rational-design-handbook-four-primary-metrics
- 視覚・音・運動・ルールの過剰情報は、プレイヤーが状況を把握し次を予測する能力を下げる。
- **翻訳**: 情報が多い画面の実現に「派手な線・光・文字を何枚も重ねる」方式は採用しない。意図ある予告・シルエット・地形の層を使う。

### G. 情報密度とUXの関係（学術研究・参考）
https://www.jstage.jst.go.jp/article/adadapic/2025/0/2025_CT0301/_article/-char/ja
- 2025年公開の個別研究では、調査対象プロトタイプにおいて視覚ディテールの密度そのものは体験評価に有意な影響を示さず、環境の物語的な質の方が大きな影響を持った。
- 他ジャンルの小規模研究結果を自動ランナーへ一般化しない。**装飾を増やせば面白くなる保証はない**という補助的な根拠に限定する。

## 実装側で発見した制約: 視認できる未来は短い

現行コードの iPad 相当 1024×768 横画面では、論理画面幅 ≈920、キャラのX ≈181。右端からキャラまでの距離は約739論理px。

- 初速400px/sでは、右端に現れた障害物までの時間は約1.85秒。
- 最高速1150px/sでは、**約0.64秒**しかない。
- これは「障害物が画面右端に初めて描画される」理論上の時間であり、装飾との重なり、端末遅延、視線移動を無視している。

**密度増加の前に、最高速での先読み時間を確保すべき**。候補:
1. 速度に応じて前方の論理表示幅を少し広げる（棒人間が小さくなる副作用を評価）。
2. 次の複合アクションの危険形状を画面右側から予告する（HUDを塞がず、実世界の配置と一致）。
3. 複雑な連携は最低限の観察猶予が得られる場所で開始する。

※「最高速で最低0.85秒の先読み」などの値は**設計仮説**。学校iPad実機と本人試遊の評価で調整する。

## 次期 V0.7 の具体的な品質計測（現時点では未達成）

| 指標 | 数え方 | 失敗する設計 |
|---|---|---|
| 重要操作/10秒 | ジャンプ、追加ジャンプ、しゃがみON/OFFの発生数 | 単調なジャンプ連打で増加 |
| 連携フレーズ比率 | 2〜4種類の意味の違う動きを連続して要求する区間率 | 違う障害物名だが同じ操作 |
| 地形遷移 | 地上↔空中、足場間、高低差、着地を伴う場面/30秒 | 背景に足場があるだけ |
| 可視予告秒数 | 進路上の危険をプレイヤーが識別できてから到達するまでの最短秒数 | 画面外から即衝突 |
| 空白・単調な区間 | 何秒間「重要操作も前方情報もない」状態が続くか | 長い平地、同パターン3連続 |
| 視覚可読性 | 危険物輪郭、予告、着地点が演出に隠れないか | 光で衝突判定が見えない |
| 入力許容率 | 各操作を独立に ±60/80/100ms ずらした連続コース突破率 | 理想入力専用コース |

既存のV0.6は序盤約8.9件/10秒、終盤約10.7件/10秒の**入力密度**が測定されていた（意思決定数や画面密度とは別）。これは出発点であり「十分」という意味ではない。

## コース設計の対比例（イメージ、現行実装ではない）

- 密度が低い: 直進 → 単独の低い箱を跳ぶ → 直進 → 同じ箱を跳ぶ → 直進。
- 悪い高密度: 既存の箱をひたすら横に並べ、背景を発光させ、見える時間を削る。
- 良い密度の候補: **下段トンネルへ滑り込む → その出口で跳躍 → 空中足場へ着地 → 上段から自然落下 → 着地を使って再跳躍**。一つの行動が次の状況を準備しており、成功すると連続した動きになる。

## 実装優先順位

1. **画面先読みの確保**: iPad最高速の予告猶予を測り、視認可能な情報量を増やす。
2. **軌道先行生成器の連続動作ルール**: 単独ギミックを増やすのではなく、動作の因果・高度の遷移・連鎖を生成。
3. **生成後の密度計測**: 操作回数・フレーズの多様性・地形遷移・先読み時間を全乱数シードで計測。速度帯ごとに比較。
4. **画面演出を後から**: 危険物の可読性を固定した上で、走路の照明・工場の機械・環境の変化・ジャスト回避の反応を追加。視覚効果で難易度を水増ししない。
5. **人間の試遊**: 「簡単」「単調」「情報量が乏しい」が改善したかを本人が判断。独立入力ジッター・iPad Safari実機で理不尽さを確認。
