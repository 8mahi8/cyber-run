## なぜ自動生成より先に作るのか

V0.7/V0.8の試遊を通じ、ユーザーは「基盤やスピード感は良いが、簡単で、ギミックが少なく単調」と評価した。
自動生成を改善しても、**何を作れば面白いかという理想コースが定義されていなければ、機械的に通れるだけの地形が増える**。

そこで先に人手で**1つの完成した有限ルート**を組み立て、その後この基準を小さな認証済みコースへ分割してプロシージャル生成器へ戻す。参考:
- 『Super Mario 3D Land』の導入・発展・ひねり・習得のレベル構成: https://www.gamedeveloper.com/design/the-secret-to-i-mario-i-level-design
- 『Spelunky』の手作りテンプレートを組み合わせたマップ生成: https://ems.andrew.cmu.edu/2014_60210a/maj/08/27/technological-artdesign-spelunky/index.html
※これらは設計上の参考であり、HYBRID生成器を実装したという意味ではない。

## このマップの遊び方

- 20セクションを**完全に固定した順序・同じ配置**で進む。ランダム生成なし。
- 約65秒で右端にある実際の「GOAL」へ到着すると終了する。
- ジャンプ・二段ジャンプ・押している間のしゃがみ、HP3、既存の速度加速・物理エンジンを維持。
- ゲーム中のHUDでセクション番号（01/20〜20/20）を表示する。
- 何度でも最初から再挑戦でき、失敗した場所を学習できる。クリア時は残HPを表示。
- ランキング/Firebaseは切り離す。最高記録はこの手作りモード専用のローカルストレージキーを使用。
- Safari/iPad本番Google Sites直接埋め込みは**まだ未検証・未公開**。本人の試遊はGitHub Pages別URLで行う。

## 人が設計した5つの難度フェーズ（各4区間）

| 区間 | ねらい | 主な操作 |
|---|---|---|
| 1〜4 | 操作の切替と最初の崩落 | 必須しゃがみ→ジャンプ→2段の足場→リズム→崩れる床 |
| 5〜8 | 地面以外のギミックに適応 | 空中リング、2回のしゃがみ、ジャンプ台、崩落後のシャッター |
| 9〜12 | 複合動作への移行 | 段差としゃがみ、リング→シャッター、高密度リズム、崩落→リング→シャッター |
| 13〜16 | 別種の地形を高速でつなぐ | 2段上昇、移動障害物、崩落の再登場、上段しゃがみ |
| 17〜20 | 習熟度の最終確認 | 複合ギミック→高密度リズム→空中リング→最終複合 |

`handcrafted-level.js` に全セクションの**作者が決めた順序・操作意図・地形/障害物設計**を固定している。既存の安全確認済みギミックを部品として組み合わせ、3セクションでは既存の「飛び越せる任意のバー」を明示的に「しゃがみ必須の通路」へ変更した（元の生成パターンそのものは変更なし）。

「素材が既存だから完成」ではない。**難度は未合格扱い**で、君が遊んで足りない場所を指摘したら、この1本の配置・数値・見せ方を直接編集し、先に面白さを確立する。

## 技術的な受け入れ状況

- Node.js 自動テスト77件成功（新規5件を含む、GitHub Actions run #39914642950）。
- 理想操作列による全20区間・約65.1秒の通過を確認。
- 操作時刻を**各入力ごと独立に±60ms**揺らしたフルマップ400試行をローカルで全件クリア。±80msでは182/200、±100msでは141/200。つまり「±100msでも誰もがクリア」は偽であり、特に必須しゃがみ→他行動の連携には技術的な習熟余地とタイミング幅がある。
- 「ジャンプだけ」「しゃがみだけ」では、物理コリジョンに衝突して最後まで進めない。
- Chromium 844×390（スマホ横）/1024×768（iPad相当）の2サイズでQA用の操作列を再生し、ゴールまでHP3・JavaScriptエラーなしで完走。スクリーンショットも確認。
- 上記は**QAの理想的な操作再生**。学校の古いiPad Safariにおける速度、画面内の危険物の読みやすさ、本人の主観的な楽しさは未確認。
- 難易度を数字だけで保証しない。既存パターンを人手で選んだ初回試作であり、さらに**オリジナルの地形・罠・操作連携**を手作業で改善する余地が大きい。

## 次の開発順序

1. **人間に手作りルートを試遊してもらい、どの区間が簡単・つまらない・読みにくいか特定**する。
2. コースの章ごとに配置と前後動作を手動修正し、毎回フル物理リプレイで「必要操作と突破可能性」を認証する。
3. 本人が「面白い、ちょうど難しい」と評価した区間だけを**認証済みの手作り部品**として保存する。
4. それらの部品を自動生成器で並べ替える際、入力余裕・前後の地形/速度・見通し・本当に必要な操作が継続することを検証する。
5. 最終段階のみGoogle Sites直接埋め込みHTMLを作り、学校iPad Safariで確認。Firebaseの歴代ランキングは仕様確定済みだが本マップと独立して開発する。
