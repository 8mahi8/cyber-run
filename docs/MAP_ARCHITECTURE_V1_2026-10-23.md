# CYBER RUN｜マップ方式・レベルデザイン V1（2026-10-23）

**状態：外部資料と既存コードを踏まえた設計案。コード未実装・試遊未検証。**
**作業対象：** dev/handcrafted-circuit-01-20261023（GitHub開発ブランチのみ）
**重要：** この設計書は新たな学校公開の許可ではない。Google Sites版、main、既存試遊版、Firebaseに変更しない。

## 0. 最新のユーザー方針（従来の引き継ぎ文より優先）

- 2D横スクロール無限ラン。距離で競い、失敗後の繰り返し挑戦と上達が目的。最初からクリアさせる必要はない。
- **初見のギミックへ必ず対処可能にする必要はない**。学習可能な初見殺しは許容。誤判定・不可避・学べない失敗は避ける。
- 最初の約8〜12秒は毎回同じ「準備運動」コースにする方針をユーザーが肯定。その後は手作り地形の条件付き自動接続を第一候補にする。
- コインは **A：スコアに一切影響しない道標専用** と決定。取得時に視覚効果は可だが通貨・スコア・ノルマにしない。
- HP3、ジャンプと2段ジャンプ、押している間のしゃがみ、希少な回復、徐々に加速し高い最高速度、単純な大穴死は避ける。
- ルート分岐を増やすこと自体は好まない。基本は一本の進路で、操作・高度・地形で変化を出す。
- 学校公開は **Google SitesにHTML/CSS/JSの単一コードを直接貼る**。GitHub Pagesは本人の試遊用。無料運用厳守。
- 今回はまず設計を固める。現行20セクションのTHE CIRCUITは既存パターンの並び替えであり「完成した面白さの基準」と見なさない。

## 1. 方式の結論（暫定推奨）

**短い固定導入 + 手作りの連続アクション片 + 物理・文法制約付き接続 + 無限ラン**。

厳密な順序：
1. まず **固定の一本の高品質な見本コース** を設計し、操作の手応えを確かめる。
2. 見本コースを単独障害物でなく **2.5〜5秒の連続操作モチーフ** に分け、さらに **6〜12秒の複合チェーン** として品質検証する。
3. 各モチーフの入口と出口の身体状態・足場・速度範囲を記録し、接続可能なものだけ生成器へ渡す。
4. プレイでは約10秒の固定準備運動の後に、距離帯に応じたモチーフ・チェーンを抽選し無限接続する。
5. 接続後の意図した動作軌道を元に、取得してもスコアが増えないコインを配置する。
6. 実装後に「同じパーツを固定順にした版」と「条件付き抽選版」を比べ、単調なら設計を改める。

いきなり自動生成器を拡張してパーツ数だけ増やすのは行わない。コースはクリア保証でなく、**少なくとも熟練操作で突破可能**であることを必須とする。

## 2. 固定準備運動（初期案・約10秒）

毎回同じ地形、同じコイン、同じ操作のタイミングにする。チュートリアル的な長い説明・空白にしない。

| 仮の時刻 | 役割 | 基本動作 | 意図 |
|---|---|---|---|
| 0〜3秒 | GATE BEAT | 必須しゃがみ通路を抜け、地上の低い障害物をジャンプ | 2入力の切り替え、指の準備。ジャンプ回避できない通路を含む |
| 3〜6.5秒 | UPSTEP | ジャンプから段差、2段目への再跳躍・着地 | 高低差と再跳躍の感覚 |
| 6.5〜10秒 | EXIT LINK | 上段から降りる→着地してしゃがむ→抜けて再ジャンプ | 着地と次の動作がつながる爽快感 |

秒数・距離・全ジャンプ位置はエンジンの軌道を使って再確定。最初の約10秒を無傷で抜けることはできるが、初回無傷を保証する意図はない。毎回同じ導入を長く感じる実機評価が出たら6〜8秒まで短縮候補。

## 3. 手作りで最初に設計する6種のモチーフ

すべて **操作を先に設計し、動作の前後を因果関係でつなぐ**。地形の色や名称だけを変えた水増しは禁止。

| ID | 仮名称 | アクションの核 | 危険・独自の学習内容 |
|---|---|---|---|
| M01 | SHUTTER SWITCH | 長押ししゃがみ→出口で解除→ジャンプ | しゃがみ解除が遅いとぶつかる |
| M02 | TWO-STEP SKY | 1段目に着地→再ジャンプで高い段→段差を降りる | 空中での連打ではなく着地によるジャンプ回数回復を学ぶ |
| M03 | FRAGILE STEP | 崩れる足場に着地→間を置かず跳ぶ→安定地面へ | 足場の保持時間を覚えて突破 |
| M04 | RING VAULT | リングへジャンプ→反発→遠い着地点→次の入力 | リングの高さと反発する軌道を覚える |
| M05 | DROP & DUCK | 上段から降下→着地直後しゃがみ通路→解除して跳ぶ | 着地しないとしゃがめないことと連続切替 |
| M06 | PULSE DRONE | 移動障害物を見切る／一度失敗して周期を覚える→次の障害へ | 動きのある危険への対応、偶然の回避のみにならない配慮 |

**長い連携のサンプル（別途手作業で完成させる）**
- CHAIN-A：M01のトンネル脱出 → M02の上段へ飛ぶ → 降下からM05の着地しゃがみ
- CHAIN-B：M03の崩落 → M04の空中リング → 着地してM01の低い通路
- CHAIN-C：M06を見切る → 地上ジャンプ → 上段の低い天井 → 安全着地

既存のcore.jsには duck-gate、fragile、airboost、spring、moving の素材があるが、これらの複合チェーンがすべて現行の物理・当たり判定で成立するとは未確認。机上の構想を完成ギミックとして扱わない。まず6種各1本を本当に作り込み、必要なら各モチーフを2バリエーションへ拡張。

## 4. コイン道標の設計契約

- スコア、ランキング、距離、HP、回復、通貨、取得義務へ一切影響しない。
- 一番想定した攻略軌道の上昇弧・着地帯・しゃがみ通路の床上などに配置する。
- 視界に入ったコインだけで攻略がすべて分かる必要はなく、失敗後に「そういう意味か」と理解できればよい。
- **実行したら即死する偽案内はしない**。誘導は攻略ヒントであり、コイン全部の回収や完全な軌道の保証ではない。
- 弧の線状配置・床付近の直線・リングへ向かう収束配置の3種を初期パターンとする。
- コインが障害物輪郭や着地地点を隠さない。極端な発光・過密は避ける。
- 軌道・地形に変更があればコイン位置を再検証する。単独でランダムに散布しない。

## 5. 生成文法：つなげられるものだけを抽選

各モチーフ・チェーンに少なくとも以下のメタデータを与える。
- entry / exit：地面または足場、高度、ジャンプ残数と接地状態、しゃがみ状態、想定鉛直速度
- speedMin / speedMax：エンジン上の検証済み速度範囲
- actions：要求動作の順番、各行動の入力許容幅（計測値）
- features：段差／しゃがみ必須／2段ジャンプ／崩落／リング／移動障害物
- difficultyCost：難度予算の推定値（**人の試遊から再調整**）
- exclusionTags：直後に同種の動作を重複させない・無理な接続を避ける制約
- coinPath：想定攻略軌道から生成する案内ポイント

**禁止する接続の例：**
- 前パーツ終了時に空中でジャンプを使い切っているのに次で即再跳躍必須
- 踏める足場も猶予もないまま即しゃがみ必須（しゃがみは接地中のみ）
- 画面を跨いだ独立パーツ間の衝突判定やギャップが未検証
- 大穴のみ・ランダム位相の即死ドローンなど、失敗しても対策が立てられない設計
- HPを必ず失わなければ突破できない配置

**許容する難しさ：**
- 初見では見切れず1〜数回失敗する
- しゃがみ解除が遅いと次に間に合わない
- 早すぎるジャンプや着地のずれで失敗
- 既知の連携が高速度で難化

抽選はプレイごとにseedを一度決め、同じseedなら地形を再現できるようにする（開発QA用）。ランダムな並びが不可能な場合は、既知の接続可能なチェーンを選んでフォールバックする。入口・出口・速度の検証を重視し、「どのパーツも絶対に初見で反応できる」は制約にしない。

## 6. 難易度・速度と緩急

現行物理は BASE_SPEED=400px/s、MAX_SPEED=1150px/s、加速度は7.5px/s²で、約100秒で最高速に届く。この曲線は現時点の出発点。視認可能時間が高速で短くなるため、初見対応保証はしないが、コイン・シルエット・コースの理解を不可能にする視覚ノイズは抑える。

| 時間帯（初期仮説） | 地形と組み合わせ | 難しさの方向 |
|---|---|---|
| 0〜10秒 | 上記固定準備運動 | 毎回同じ指ならし、単なる平坦地形にしない |
| 10〜30秒 | 6種の基本モチーフを主に使う | 既知パターンの学習、毎回違う順番 |
| 30〜60秒 | 2モチーフの接続・短いチェーン | 着地→次操作へのつながり |
| 60〜100秒 | 3アクション以上・崩落/リング/しゃがみ連続 | 操作精度と記憶による攻略 |
| 100秒以降 | 高速熟練チェーン、変化する順番 | 速度が天井でも構成の難度で限界挑戦 |

単純に障害物を毎秒増やすのではなく、連携・高度変化・操作の切り替え・速度帯で難化させる。高負荷の後に短い「呼吸できるが無操作ではない」区間を入れる。ただし緩急の秒数は試遊で調整。

## 7. 学習・ランキング・リトライ

- 通常のランは無限、GOALなし、距離の自己ベストを競う。
- 現行の約20セクション・有限THE CIRCUITは **地形研究の固定テストベンチ** として別扱い。無限ランの公開仕様と混同しない。
- HP3の仕様を保持。被弾後無敵が「しゃがみ必須を無視して突っ切る最適戦術」にならないか検証する。
- レア回復は走路破綻を招かず、ランキングに過度の運差を持ち込まない位置を検討。
- ランキングは既存決定どおり全期間ベスト距離。生成順による有利不利は残るため、**シード固定ランキングや大会方式などは未決定**として扱い、無断変更しない。
- 過去のチャット方針どおり、対戦履歴や自動学習システム等の余計な機能を足さない。すぐ次の挑戦を始められることを重視。

## 8. 比較試遊と品質ゲート

**第一段階：手作り一本の成立**
1. 固定導入と6種モチーフの動作をまず単独で確かめ、次に人間が操作して面白いか確認。
2. 物理シミュレーション 120Hz にて、ゼロ被弾で通過できる少なくとも1経路を示す。
3. 連携部では各入力を独立に±60/80/100msずらし、破綻率・許容幅を記録。**すべてのずれに耐える必要はない**（高難度を殺さない）。
4. 「学べる失敗／不明瞭な失敗／判定バグ」を分けて人のテストで判断。

**第二段階：マップ方式A/B比較**
- A：同じ手作りパーツを固定順で接続
- B：同じ手作りパーツを制約付きseedランダム接続
- （余裕があればC：チェーン単位の制約付き接続。最初からCを作り込みすぎない）
- 速度曲線・HP・コイン・障害物数の大枠を揃える。
- 3〜5回繰り返した時の「再挑戦したさ」「学習できた感覚」「単調さ」「操作が忙しいだけになっていないか」を本人評価。客観指標はミス箇所、操作の異なる動作数、地形高度変化、速度別パターン偏り。
- 少数の自動テストだけで完成宣言しない。学校iPad Safari・Google Sites直接埋め込みで最終確認。

**第三段階：無限接続の堅牢性**
- seedを大量に変え、速度帯別に検証。隣接チェーン境界、移動障害物位相、無敵時間、しゃがみ継続、画面回転、長時間メモリ・描画負荷を検証。
- 実機でのランと順位表示はランキング接続が別途許可・検証されてから実施。
