# CYBER RUN｜手作り研究コース V2 実装・初回検証（2026-10-23）

**状態：開発ブランチのみの技術試作品。人間の面白さ評価、実ブラウザ目視、旧iPad Safari試遊は未完。学校公開・無限ラン本体には未統合。**

## 目的と方針
- 再挑戦・学習によって記録を伸ばすゲーム。初見対応の保証は不要。
- 序盤だけ同じ地形（準備運動）、後に手作りの連携アクションを置く。
- コインは道標だけ。HP・距離・スコア・ランキング・通貨に影響させない。
- 以前の手作り20パターンの羅列を完成品だと誤認しない。独創性のある地形を増やし、徐々に手作り品質を上げる。
- 外部資料：*Sure Footing* の動作→地形→予算とつなぎ方、*BIT.TRIP RERUNNER* のギミック誘導・フローの考え方を参照。
  - https://www.gamedeveloper.com/design/keep-running-procedural-level-generation-in-sure-footing
  - https://www.rerunner.game/tutorial

## このターンで開発ブランチに追加したファイル
- `handcrafted-level-v2.js`：13セクションの研究用固定コースと、物理証拠の移動軌道から道標コインを作る実装

## マップの構成

- 最初の障害物まで短い導入移動あり。固定準備運動の終点はスタート約9.75秒。
- 全13セクション、想定コースの終点は約42.49秒（現在は有限GOALの技術試作）。
- 設計原則は連続操作、上段・下段の地形変化、強制しゃがみ、崩落、空中リング。
- 道標コインは全136個。正規のクリア軌道をコア物理の120Hzリプレイで追跡し、約0.255秒ごとに配置。
- 1〜3：GATE BEAT → UPSTEP → EXIT LINK（固定準備運動）
- 4〜10：SHUTTER SWITCH → TWO-STEP SKY → FRAGILE STEP → RING VAULT → PULSE DRONE → FRACTURE SHUTTER → BROKEN CIRCUIT
- 11：**SWITCHBACK RELAY：新規手設計の4.4秒地形。** 必須しゃがみ → 解除して高台ジャンプ → 高台着地 → 再跳躍 → 地上着地 → 必須しゃがみ → 解除 → 最後のジャンプ。高さ77pxの高台と両端のゲートが実際の動きを要求する。
- 12〜13：RING TO CRAWL → FINAL RHYTHM

**重要な品質上の留保：** 今回はエンジン・既存パターンの再利用がまだ多い。SWITCHBACK RELAYだけは新しい複合地形として制作したが、これは「完全な手作り高難度マップが完成した」ことを意味しない。

## 初回の物理検証結果

- 使用：実際の `core.js` をV8で実行して `C.buildPattern`, `C.physicsStep`, `C.replayPattern` を呼び、プレイヤーと障害物を統合した連続120Hzシミュレーション。
- 13セクションを**同一プレイヤー状態で連結**し、想定操作で全区間被弾なし・落下なしを確認。
- 隣接する入力イベントのズレを交互に与えた連続操作テスト：
  - 0ms / ±25ms / ±45ms / ±60ms / ±80ms：全コースで被弾・落下なし。
  - ±100ms：10.225秒付近の必須しゃがみゲートで失敗。高難度を残す設計なので直ちにバグとは判断しない。
- 新規 `relay-bridge` の単体物理検証：開始時刻0・10・20・40・70・100秒で成功。最初の高台着地およそ1.30秒、地面帰還およそ2.41秒、最後の地面着地およそ4.08秒（各区間の相対時刻）。
- コイン数、各コインの所属セクション内の座標、取得によるスコア変更がない実装をチェック。

**検証範囲を誇張しないこと：** これは理想操作のプログラムシミュレーションとソース構文チェックであり、手動ブラウザ操作やiPadの実機で最後まで遊べた証拠ではない。Webページのランタイム・視認性・操作難度・面白さ・演出の完成度は未検証。リポジトリにテストスクリプトは配置したが、GitHub Actionsでの実行履歴はこの時点で未取得。

## 残る問題と次の作業

1. 固定試作品を実ブラウザで起動・タッチ入力・描画・GOALまで検証する（環境が用意できる時点で）。プレビューはGitHub Pages用の独立URLのみ、学校版を上書きしない。
2. 手作り固有のチェーンをさらに複数制作し、既存パターンの単なる羅列から脱する。各地形は理由のある操作・入力切替・上段/下段の違いを持つ。
3. 本人に試してもらい「簡単／単調」がどれだけ改善したかを判定。最初の9.75秒が長ければ短縮。
4. 固定コースが良い評価を得てから、モチーフ入口・出口・速度と難度予算を持つ条件付き生成器、シード固定QAを実装する。
5. 無限ラン・Firebaseランキング・Google Sites直接埋め込みは別作業。試作が良さそうでも学校の公開版を無断で切り替えない。
