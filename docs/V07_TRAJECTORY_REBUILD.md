# CYBER RUN V0.7｜試遊フィードバック起点の再設計

状態: **EXPERIMENTAL / 本番・V0.6試遊ページへ反映しない**（2026-10-23）

## なぜ作り直すか

ユーザー実機試遊の評価:
- 基盤の良さとスピード感は改善した。
- 難易度はまだ低い。
- 操作中に意味のある情報・判断が少なく、ギミックやコース展開が単調。
- 「先にキャラクターの動きを想定してからマップ生成する」設計になっているか疑わしい。
- 棒人間の走り方が不自然。

### V0.6の事実関係

既存の約28パターンは、**固定された障害物位置・固定された操作スクリプトを対として定義した**データである。生成時は抽選・微少な時間ズレ・同テーマ反復抑制を行い、物理リプレイで突破可能性を検査する。これは「移動軌道を先に生成し、そこから地形を作る」設計と同じではない。ユーザーの指摘は正しい。

## V0.7の変更（実装済み、実験ブランチ）

1. まず `trajectoryComposition` がジャンプ・2段ジャンプ・しゃがみ・連携・溝越え・空中足場の**行動列だけ**を生成。
2. `trajectoryTrace` が実ゲームと同一の `physicsStep` を使用し、1/120秒刻みで主人公の位置・足元・しゃがみ状態・足場支持状態を算出。
3. `composeTrajectorySegment` がその軌道を観察して障害物・溝を配置。空中足場は仮の落下軌道から着地点を計算して作る。
4. 地形を入れた状態でもう一度軌道をシミュレートし、必要な入力列が成立することを検証。成立しない候補は棄却する。既存V0.6生成器はフォールバックとして保持。
5. 走行アニメーションは接地脚と遊脚を分け、反対側の腕を振る方式へ変更。姿勢計算のみで当たり判定は変えない。

### まだ合格ではない

**新生成器は標準ゲームへ自動で有効化しない。** `CYBER_RUN_V07_EXPERIMENTAL === true` の明示的な実験スイッチが必要。PR #2はDraftで、V0.6公開版・V0.6試遊ページは変更しない。

最初の統合テストで次の回帰が出た:
- 連結コースで独立した±60〜100ms入力ズレを加えたときの無被弾成功率がV0.6より下がる。
- 序盤に空中ギミックが登場する比率を十分保てないケースがある。
- 長い生成区間では旧検証器の固定1000ステップ上限に引っかかることを発見し、動的ステップ上限へ修正。
- 空中足場の生成成功と「人間の入力ズレに対する寛容さ」は別の問題である。
- 新生成器の障害物密度は依然として薄い可能性があり、**生成方式が変わっただけで難易度が上がったとは判断しない**。

## V0.7を試遊へ出すための次の品質条件

- 既存の独立入力ジッター検証でレガシーより悪化させない。各操作を一斉にずらすのではなく、別々にずらして検証。
- 前半と後半の1画面あたりの重要な判断回数、障害物の種類の組み合わせ、空中移動の占有率を監査。
- 「避けるだけ」ではなく、足場へ飛び移る・溝を越える・高低を変える・ジャンプ後にしゃがむ等の**違う行動**が増えることを確認。
- 高速時に危険物が判別でき、画面演出がそれを隠さない。
- 棒人間の接地と手足の連動を実ブラウザで確認。
- 既存の物理・入力・ルート・タッチ自動テストに合格させてから、**別のGitHub Pages試遊URL**で本人評価。旧ページは触らない。

速度上限1150px/s、完全無料、距離スコア、学校iPad Safariの横画面への対応は維持。

## 外部調査に基づく「情報密度」の追加品質ゲート

調査文書: [V07_INFORMATION_DENSITY_RESEARCH.md](V07_INFORMATION_DENSITY_RESEARCH.md)

単なる障害物の個数や画面の装飾数を増やすのではなく、①意味のある操作、②連携した状況・高低差変化、③予測できる情報、④危険物を隠さない演出を別々に評価する。特に現行iPad相当横画面では1150px/s時の右端からの予告時間が約0.64秒に過ぎず、密度増加前に視認性・先読み時間を検証する。

## しゃがみを必須にする設計の修正（2026-10-23）

ユーザーの新たな指摘: 「しゃがむギミックのほぼ全部がジャンプで避けられるなら、しゃがむ理由がない」。これを単なる見た目の問題ではなく、**操作ごとの役割が成立していない設計欠陥**として扱う。

### 必須ギミックと自由選択ギミックを分ける

- `bar`: 頭上からの障害物。ジャンプで飛び越す、しゃがんで通る等の自由な攻略を残す。
- `duck-gate`: 頭上の大型シャッターで、床上に**28pxの抜け道だけ**を残す。障害物は `y=GROUND-300` から `GROUND-28` まで連続し、地上からの通常ジャンプ・2段ジャンプ・ジャンプ台では上から越えられない。実際のコリジョン矩形全体を描画し、隠れた当たり判定を作らない。
- 地上でしゃがむと通常の48px衝突高さが27pxになり、低い抜け道を通れる。ゲートの前後にはジャンプ等を組み合わせる。
- 全てのしゃがみ障害物を強制にするのではなく、自由な攻略選択と**必須の判断**を混在させる。

### 今回の実装

既存の6種の行動パターン（`reverse-switch`, `tunnel-run`, `duck-weave`, `beam-chase`, `pulse-drone`, `drop-and-duck`）に必須ゲートを一部導入。V0.7の軌道先行生成器でも `slide` / `slide-vault` を必須ゲートに変え、`vault-slide` では任意のバーを維持した。

`tests/duck-necessity.test.js` に以下の回帰検査を追加:
1. 通常姿勢ではゲートに接触するが、しゃがんだ衝突矩形は通過する。
2. 物理的に最大高度へ到達するダブルジャンプやジャンプ台でも、ゲート最上部を越えられない。
3. 必須パターン6種を速度帯0/22/100秒相当で検査。想定操作は完走し、しゃがみの操作を削除したりジャンプに置き換えたりすると衝突。
4. 自由攻略バーも十分残っていること。
5. コース抽選で必須ゲートが一定頻度で発生し、実験的な軌道先行生成にも同じ要件が反映されていること。

ローカルの物理シミュレーションでは、抽選500シード×初めの30秒のうち499シードに必須ゲートが出現（合計1778個、30秒あたり平均3.56個）、自由選択の `bar` は合計2447個。**この数字は「おもしろさ」や「難易度が十分」を示すものではない**。

PC上のChromiumでスマホ横・iPad相当を各120秒のQA自動入力で走行したところ、HP3を維持して最高速度1150に到達し、JavaScriptエラーなし。学校iPadのSafari実機ではまだ未検証。

**V0.6試遊版と本番のGitHub Pages/Google Sitesは一切変更せず、V0.7 Draft PR #2のみで開発する。** ゲーム全体の難易度とアクション情報密度は引き続き調整・ユーザー試遊が必要。


## 高密度アクションの物理監査と先読みUI（2026-10-23）

ユーザーの「情報密度が薄い」「ただ高速なだけでは簡単」という試遊感想を受けた追加作業。

- **コースを短くつなぐ実験**: 行動テンプレート内のジャンプ時間・重力を弄らず、異なる動作同士をつなぐ間隔だけを短縮。20秒以降では約55ms、55秒以降では約150ms。物理的に成立しない経路をそのまま採用しない。
- **入力の独立した前後ずれを検証**: `replayPattern` に各操作ごとの `actionOffsets` を追加し、4種類の±100ms前後のずれを加えて再計算。従来の「全入力をまとめて同じ秒数ずらす」検証だけでは許容しない。ずれで通れない候補は棄却。
- **最大3候補の再構成**: 失敗した行動案をそのまま強引に使わず、別の行動案から描き直す。3回とも駄目なら安定した従来のコースへ戻す。V0.7軌道先行生成器は引き続き実験スイッチで明示的に有効化した場合のみ使う。
- **機械的な密度の計測**: 240シード、最初の0秒と120秒での有効な合成ルートを比較したローカルサンプルでは、操作回数換算で序盤約10.8回/10秒→後半約11.8回/10秒。後半でも空中区間、しゃがみ必須と自由攻略の両方が発生することを確認。**これは新生成器の採用ルートだけの指標であり、ゲーム全体の体感難易度や本人の面白さを保証しない**。
- **最高速度における先読み**: 画面の地面レイヤー中央に控えめな `SCAN` ラインを設け、約1.5秒先までの実際の障害物・溝のシルエットを最大5個まで表示。動作ボタンの正解は書かず、危険物の種類だけを知らせる。小画面では非表示、初速時にも邪魔をしない。
- **再現可能なブラウザQA**: `tests/v07_trajectory_browser_qa.py` は通常版には存在しない実験スイッチをQA環境のみで有効化し、受理済みコースの行動列を再生する。スマホ横844×390・iPad相当1024×768のChromiumで120秒ずつ走行、HP3、最高速1150、JavaScript例外0。Safari実機・人間の楽しさは未検証。
- **GitHub Actions**: 追加したルート密度・独立入力ゆらぎテストを含む61件が成功（run `39818642936`）。旧版のルート生成器の入力許容テストを削除したり、許容閾値を下げたりはしていない。

### 残課題

- 生成器を有効化しているのはQA/実験環境のみ。多くのプレイヤーが実際に触るV0.7試遊版としては、さらにブラウザ実機の操作感・情報密度評価が必要。
- 現時点の高密度化は約1割の指標改善で、ユーザーが感じる単調さを解消できたかは不明。ギミックの**行動因果・段差遷移・選択の理由**をさらに深める。
- 高密度化した場合でも、各場面のスキャナー情報が多すぎて視認性を損ねないかレビューを続ける。スキャナーを操作補助として必須にしない。

**公開状態は変更しない**: 本番V0.5、試遊V0.6、Google Sitesはそのまま。V0.7はDraft PR #2。
