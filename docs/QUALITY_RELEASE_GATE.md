# CYBER RUN｜次期版の受け渡し品質ゲート

最終更新: 2026-10-23

## 絶対ルール
**AIは安全なコース生成・操作・描画・動作の技術品質をゲートとして確認する。面白さの最終判定はユーザーの実際の試遊で行う。** 自動テストだけで「面白い」と断定せず、逆にAIが主観的な満足を得られないことを理由に試遊を無期限に延期しない。

## 1. バグ検証
- 開始直後の急加速／プレイヤーが画面外へ飛ぶ／着地判定の喪失／HP処理の破綻がない。
- 速度上限付近を含めた長時間走行、多数の乱数シード、チャンク接続のパターンを検証。
- 120 Hz相当の物理リプレイに加え、実ブラウザでの連続プレイ、タッチ入力、連続ジャンプ、長押ししゃがみ、自然落下、ポーズ連打、画面回転、タブ復帰を試す。
- iPad Safari実機確認はモデル側だけではできない。Chromium等のエミュレーション結果を実機検証済みとは呼ばない。

## 2. 「面白さ」の審査（ユーザー試遊で不合格だったポイント）
- 最初の数秒からジャンプ・しゃがみ・足場を使う移動の変化が感じられること。
- 単なる low/bar の順番入れ替えを別アクションとして数えない。
- 足場が単なる飾りにならず、「空中に乗る→駆け抜ける→自然落下」の展開を実際に体験できること。
- 速度が高く、連続操作の爽快感があり、かつ視認できること。
- ただの乱数生成ではなく、操作テーマから安全なコースを構成する。
- ギミック数や難易度数値で満足せず、画面上の操作シーケンスを観察して自己評価する。
- 最低1つの無被弾ルートと十分な入力猶予を検証。別解は歓迎。

## 3. 出荷前のテスト実施手順
1. `node --test tests/*.test.js` で物理・長時間走行・チャンク連結・入力復帰を確認。
2. `node tools/gameplay-quality-gate.cjs` で最低100個の乱数シードの序盤コース多様性を点検。数値は警告指標であって、面白さの証明ではない。
3. 実ブラウザで操作して、少なくとも複数回（序盤/中盤/最高速度付近を含む）の挙動とスクリーンショットをレビュー。自動操作だけでなく「どんな操作体験か」を記述する。
4. 深刻な技術的問題が見つかれば開発ブランチのみ改修→再検証。合格するまでGitHub Pagesの `main` や学校用Google Sitesを更新しない。
5. 技術ゲート通過時には、**公開版とは別の単一HTML試遊候補**を渡し、残る制約も説明する。ユーザーの感想（単調さ・理不尽さ・爽快感）で次の調整を決める。試遊候補の提供は正式公開を意味しない。

## 現行 V0.5 の審査結果
**NOT READY / 不合格**。100シードの30秒分コース抽選において序盤12秒の地上コース比率約90.8%、空中コース9.2%。動く障害物を含むコース0。技術的に走れても面白さがないという実際のユーザーフィードバックに一致。現行版を「完成」「品質合格」とは扱わない。
